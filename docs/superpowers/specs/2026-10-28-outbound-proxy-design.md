# 全局服务端出站代理设计

## 目标与范围

在设置页面提供全局服务端出站代理配置，支持用户部署局域网代理网关。代理覆盖 Toonflow 服务端使用全局 `fetch` 的出站请求，以及 provider 注入的 `tool.fetch`；当前 pi-ai 的 API 适配器和 ModelRuntime 沿用运行时全局 `fetch`，因此也会覆盖。若未来 SDK 使用自有 socket/dispatcher，则需在该 SDK 集成点单独接入，本功能不声称覆盖绕过全局 fetch 的第三方传输。浏览器到 Toonflow 自身 API 的请求不经过该代理。

## 方案与生命周期

服务端新增网络代理运行时模块，保存原始 `globalThis.fetch` 和当前代理值。`configureOutboundProxy(value)` 先完成 URL 校验，再原子替换当前代理值；包装函数每次调用都强制使用当前代理，忽略调用方传入的 `init.proxy`，以保证全局策略，其他 `RequestInit` 字段和 `this` 语义保持不变，并复制原始 fetch 的 `preconnect` 等静态属性。关闭代理时恢复原始 fetch 引用。

`createApp` 在动态路由和 provider 初始化前配置启动代理。启动时若已有非法值，采用 fail-safe：记录脱敏后的警告并禁用代理，应用继续启动。设置保存先校验并持久化；运行时更新只执行内存切换，不产生可失败的 I/O，因此保存成功后立即生效。更新发生在单个同步赋值点，正在执行的请求继续使用其调用时捕获的代理配置，新请求使用新配置。

## 代理地址校验

允许 `http:`、`https:`、`socks5:`、`socks5h:`，必须有非空主机；端口若存在须为 1–65535；允许 IPv4、域名和 IPv6，允许 URL 编码后的用户名/密码。去除首尾空白后规范化保存；路径只允许空路径或 `/`，查询和片段必须为空。空字符串表示关闭代理。校验错误只返回通用提示，不回显用户名、密码或完整代理 URL；日志同样只记录协议和主机端口。

## 设置界面

设置侧栏新增“网络代理”页面。页面包含代理地址输入框和说明，示例为 `socks5://127.0.0.1:1080`；留空关闭代理。输入框使用 `type="password"` 隐藏可能存在的凭据，但允许用户编辑和清空；当前值由设置初始化展示。保存沿用现有 settings store 的深度监听和保存队列，保存错误显示通用错误消息。

代理凭据会随现有设置接口返回前端并写入权限为 `0600` 的 settings 文件，这是本功能接受的现有设置模型；页面不主动展示明文，日志和错误不泄漏凭据。

## 服务端改动

新增网络代理运行时模块并通过 `utils.ts` 统一导出。`app.ts` 在动态路由加载前应用当前设置；设置保存路由增加 `network.outboundProxy` 字段 Zod 校验，并在持久化成功后更新运行时。无效输入返回 400；代理连接失败保持底层错误语义，不自动绕过代理。

## 验证

执行服务端 `bun run typecheck` 和构建。手动使用临时配置目录验收：合法代理启用、空值关闭、非法协议/主机/端口/路径拒绝、代理不可达时请求失败且不直连、保存后新请求即时切换、关闭后恢复直连，以及直接 `fetch` 与 provider `tool.fetch` 都读取同一运行时配置。禁止新增测试文件。
